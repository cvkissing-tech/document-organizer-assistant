## 结论边界

当前600组数据是确定性生成的**工程校准与回归语料**，用于防止代码修改造成明显退化。它不是从真实用户文件中独立抽取的人工标注验证集，因此：

- 不能宣称“真实用户准确率100%”；
- 不能宣称已经通过95%的产品发布门禁；
- 尚缺至少150组真实、人工独立标注的版本文件对，以及足量真实反例；
- 真实语料应在阈值固定后一次性验收，不能反向用于调参。

## 语料构成与冻结

| 项目 | 数量 | 用途 |
|---|---:|---|
| 总文件对 | 600 | 固定ID 1–600 |
| ENGINEERING_CALIBRATION | 400 | 工程期规则检查，可用于通用阈值校准 |
| ENGINEERING_REGRESSION | 200 | 固定合成回归集，不称为独立验证集 |
| VERSION | 180 | 版本关系，进入精确率与召回率分母 |
| NOT_VERSION | 360 | 普通反例和强冲突反例 |
| EXACT_DUPLICATE | 60 | 完全重复，单独统计，不进入版本指标 |

`ENGINEERING_REGRESSION`固定为ID可被3整除的200条记录。测试同时断言完整ID清单和规范化换行后的CSV SHA-256，防止样本或分割被静默修改。CSV解析器支持引号字段、字段内逗号和双引号转义。

语料覆盖中文、英文、PDF、Word、Excel、PowerPoint、版本词、年份、章节、作业与课程编号、同名非版本、跨目录、时间/大小/内容信号缺失。每行文件名具有唯一的`caseaaa`至`caseaxb`场景命名空间，使不同CSV行明确表示不同主题；测试断言600个命名空间唯一，且同一行的两份文件使用相同命名空间。CSV里的`contentSimilarity`只是“正文提取完成后”的受控输入，不验证真实PDF或Office解析过程。

## 工程回归链路

测试不是逐对直接调用评分器，而是：

1. 先把每组`EXACT_DUPLICATE`折叠为一份逻辑代表文件，再构建全部文件、词权重和候选，避免重复副本占用候选预算；
2. 把整批逻辑文件送入生产`boundedNameCandidatePairs`，并用整批逻辑文件计算`NameCorpusWeights`；
3. 若标注VERSION对未进入候选集，直接计为假阴性；
4. 生产候选器生成的每一对都进入评估，所有预测为HIGH的候选都进入精确率分母，不能只评分CSV预配对；
5. 同一行使用CSV的受控`contentSimilarity`；跨行候选按明确的NOT_VERSION真值处理，并使用`ContentEvidence.Available(0.0)`作为受控正文信号；
6. 使用与`RelationAnalysisCoordinator`共享的候选资格和信号构建函数，按生产顺序处理格式/受保护标识冲突及`VersionSimilarityScorer`。

强冲突不根据说明文字直接判定。测试使用生产`NameSimilarityScorer`实际返回的`ConflictCode`，并验证CSV声明的YEAR、CHAPTER、ASSIGNMENT冲突确实出现；其中作业编号和课程编号当前都映射为生产枚举`ASSIGNMENT`，测试分别覆盖。强冲突误报定义为“实际出现阻断冲突但最终仍为HIGH”。

## 候选规模与公平性保护

生产候选器按以下阶段调度，顺序本身也是被测试保护的规则：

1. **精确核心名覆盖阶段**：所有精确核心名桶先按桶公平轮转。偶数桶用`n/2`条稳定matching边，奇数桶用`ceil(n/2)`条边，让成员先各参与至少一次。若所有精确桶的覆盖需求之和不超过全局10,000对，弱来源不能抢占这部分预算；若需求超过10,000对，则在精确桶之间轮转分配。
2. **小精确桶完整比较阶段**：当桶内每份文件的完整比较度数`n-1 <= 128`，且组合数`n(n-1)/2 <= 10,000`时，候选器尝试保留全部组合。多个小桶合计超过剩余全局预算时，仍按桶公平轮转，不承诺全部完成。
3. **剩余候选阶段**：大型精确桶扩展、去保护标识核心名桶和强词元桶公平轮转，分享覆盖和小桶完整比较之后的剩余预算。因此弱来源在有剩余预算时仍有候选机会，但不会反过来挤占可完成的精确核心名覆盖。

候选稳定身份选择`sourceId + uri`，不使用数据库自增文档ID；测试会打乱输入并重新分配文档ID，再按URI比较候选关系。去保护标识和词元桶按稳定身份抽样最多80份文件，每桶最多512对。

大型精确桶不会计算全组合。覆盖阶段之后，扩展候选只从有界邻域生成，并按“同一可靠父目录、修改时间差、大小比例、稳定文件身份”排序：父目录、修改时间、大小和稳定身份序列各观察最多8个邻位，每类信号最多加入10,000个候选。该过程不读取正文，复杂度由排序主导，约为`O(n log n)`，而不是`O(n²)`；最终仍受全局10,000对和单文档128对限制。

| 保护项 | 上限/结果 |
|---|---:|
| 全局候选硬上限 | 10,000对 |
| 单文档硬上限 | 128对 |
| 去保护标识/词元桶文档采样上限 | 80份 |
| 去保护标识/词元桶候选硬上限 | 512对 |
| 精确核心名覆盖 | 覆盖需求总和≤10,000对时，保证所有成员至少参与一次 |
| 小精确桶完整比较条件 | `n-1 <= 128`且`n(n-1)/2 <= 10,000` |
| 5,000份高频“报告”数据 | 10,000对；单文档实际最大49对 |
| 5,000份全组合 | 12,497,500对 |
| 实际候选占全组合 | 约0.0800% |
| 100份同核心名小桶 | 4,950对，全部合法组合均保留，每份度数99 |
| 1,000份同核心名对抗桶 | 10,000对，1,000份全部参与，输入重排后关系集合不变 |
| 10个×1,000份精确桶并叠加弱来源 | 10,000对；10,000份精确桶成员全部参与；弱来源1,692对 |
| 21个×1,000份精确桶覆盖需求超限 | 10,000对；各桶参与952–954份，跨桶公平 |
| 12,000份、1,200个父目录的精确桶 | 父目录中间候选严格为10,000对；最终候选10,000对且全部文档参与 |
| 200份普通高频词元大桶 | 2,889对，不再因超过80份而整桶丢弃 |
| 20,001份同核心名极端桶 | 达到全局10,000对，覆盖20,000份，稳定遗漏1份 |

测试还断言：1,000份对抗桶全成员均有候选；相同输入重复运行结果一致；输入重排并重新分配数据库ID后，按URI得到相同关系；大型噪声语料中的已知明确版本对仍被保留。
另有一组“一份文档同时进入8个候选桶”的对抗数据；如果没有单文档保护，它可连接320份文档，测试确认生产候选器会在128对处停止。

精确覆盖的数学边界是`Σ ceil(nᵢ/2) <= 10,000`：满足时，每个精确桶的全部成员都能参与至少一对；超过时，任何算法都无法在不突破全局上限的前提下覆盖所有成员，当前实现会在精确桶之间公平轮转。单一精确桶最多可用matching覆盖20,000份文件；20,001份时按稳定文件身份确定性覆盖20,000份，稳定遗漏1份。生产代码目前没有为遗漏文件提供后续补扫，这是已知极端边界限制。

当前只验证了**候选数量和来源公平性**，没有验证端到端扫描耗时、正文提取耗时或真实内存占用，这些仍需真实设备测试。

## 后续真实发布门禁

1. 冻结算法、阈值与真实语料抽样方案；
2. 收集至少150组真实人工标注VERSION，并另行收集EXACT_DUPLICATE和多类型NOT_VERSION；
3. 标注人员不能看到算法预测结果；
4. 固定独立验证集后只运行一次发布验收；
5. 只有独立真实集高可信精确率达到95%以上、召回率达到约定目标且强冲突零误报，才能对外声明对应结果。
